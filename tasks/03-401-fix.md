# 03 — 401 silent-drop data-loss fix ✅

**Status:** shipped to main.

**The bug:** a signed-in user whose access token lapsed (common on mobile/multi-device — Supabase rotates refresh tokens) got a 401 on writes; the old code saved the record to that device's localStorage and reported `ok:true`, so the outbox **dropped it** with no banner. Real progress stranded on one device — this was the root of the whole cross-device saga.

**The fix:** a 401 now forks on auth state. Signed out → save local (unchanged, correct). Signed in → refresh the Supabase session and retry once; on success the write lands, on failure it stays queued and shows the banner. Never silently dropped. Same treatment added to the sign-in migration replay (`migrate-local.ts`), so a lapsed token no longer stalls the phone's sync mid-drain.

Files: `progress-write.ts` (pure decision, unit-tested), `auth-mode.ts`, `auth-mode-init.tsx`, `progress-fetch.ts`, `migrate-local.ts`.
